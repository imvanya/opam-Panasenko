## Завдання 2. Вилучення елементів, що дорівнюють першому (c = 3)

Перший елемент основного списку дорівнює -7. Значення запам'ятовується в `target` до початку вилучення. Інакше після `RemoveAt(0)` на нульовому місці опинився б інший елемент, і порівнювали б уже з ним.

```
основний список: [-7, -8, -3, -2, -3, -4, 9, -1, -6, 8, 1, 0, -9, 6, 2, -4, -1, -7, -6, -4]
Хибний (з початку):  [-8, -3, -2, -3, -4, 9, -1, -6, 8, 1, 0, -9, 6, 2, -4, -1, -6, -4]
  пропущено елементів, що дорівнюють -7: 0
Цикл з кінця:        [-8, -3, -2, -3, -4, 9, -1, -6, 8, 1, 0, -9, 6, 2, -4, -1, -6, -4]
Новий список:        [-8, -3, -2, -3, -4, 9, -1, -6, 8, 1, 0, -9, 6, 2, -4, -1, -6, -4]
Варіанти 2 і 3 збігаються: True
RemoveAll (додатково) збігається: True
Оригінал не змінено: [-7, -8, -3, -2, -3, -4, 9, -1, -6, 8, 1, 0, -9, 6, 2, -4, -1, -7, -6, -4]
```

**Що пропускає хибний варіант.** Цикл `for (i = 0; i < Count; i++) if (list[i] == target) list.RemoveAt(i);` після вилучення зсуває наступний елемент на місце `i`, а `i++` перестрибує через нього. Тому пропускається кожен шуканий елемент, який стоїть одразу після вилученого.

На основному списку помилки не видно: два значення -7 стоять далеко одне від одного (на позиціях 0 і 17), а після нульового елемента іде -8, тож пропускати нічого не довелося («пропущено: 0»). Щоб побачити помилку, додано демонстраційний список з трійками поспіль:

```
демонстраційний список: [3, 3, 3, 1, 3]
Хибний (з початку):  [3, 1]
  пропущено елементів, що дорівнюють 3: 1
Цикл з кінця:        [1]
Новий список:        [1]
Варіанти 2 і 3 збігаються: True
RemoveAll (додатково) збігається: True
Оригінал не змінено: [3, 3, 3, 1, 3]
```

Хибний варіант лишив одну трійку, правильні варіанти дали `[1]`. Цикл з кінця безпечний, бо вилучення зсуває лише елементи правіше за `i`, а вони вже перевірені.

## Завдання 5. Замір часу

Конфігурація Release (`dotnet run -c Release`), перед заміром зроблено прогрівальний прогін на 1000 елементів, який не враховується. Кількості не зменшувалися, бо `Insert(0, x)` працював значно менше 30 секунд.

| Що міряємо | Час, мс |
|---|---|
| 100 000 × Add(x), список без заданої місткості | 2,319 |
| 100 000 × Add(x), new List<int>(100000) | 0,389 |
| 100 000 × Insert(0, x) | 312,825 |
| 1 000 × Contains(значення, якого немає) у списку з 100 000 елементів | 11,120 |

```
Insert(0, x) / Add(x) = 134,9 разів
Add без місткості / Add з місткістю = 5,96 разів
```

**1. У скільки разів `Insert(0, x)` повільніший за `Add(x)` і чому.** Приблизно у 135 разів (312,825 мс проти 2,319 мс). `List<T>` усередині тримає масив. `Add` пише елемент у першу вільну клітинку в кінці, тобто за сталий час. `Insert(0, x)` має спершу зсунути вправо всі елементи, що вже є, щоб звільнити нульове місце, тобто копіює в середньому n/2 елементів на кожну вставку. Для 100 000 вставок це близько n²/2 = 5·10⁹ переміщень, а `Add` робить лише близько n = 10⁵ записів. Різниця в часі «лише» у 135 разів, а не в десятки тисяч, бо зсув виконується одним швидким блоковим копіюванням пам'яті, а не поелементно. Складність при цьому все одно квадратична: при подвоєнні кількості вставок час зросте приблизно вчетверо.

**2. Чому заздалегідь задана місткість дає виграш.** Без місткості внутрішній масив починається з малого розміру й щоразу, коли заповниться, подвоюється: виділяється новий масив удвічі більшого розміру і в нього копіюються всі наявні елементи. Для 100 000 елементів таких перевиділень близько п'ятнадцяти, сумарно копіюється порядку 2n елементів, і додатково зростає навантаження на збирач сміття. Якщо місткість задана одразу, масив виділяється один раз і копіювання зникає. Кількість самих `Add` не змінюється, економиться саме перевиділення пам'яті та копіювання. У нашому заміру виграш становить близько 6 разів (2,319 мс проти 0,389 мс).

**3. Чому `Contains` тисячу разів помітно довший за сто тисяч `Add`.** Значення, якого немає, `Contains` шукає лінійним проходом по всьому списку, бо зупинитись достроково він не може. Один виклик це 100 000 порівнянь, тисяча викликів це 10⁸ порівнянь, тоді як сто тисяч `Add` це лише 10⁵ записів. Складність одного `Contains` O(n), а амортизований `Add` O(1). У часі різниця виявилась скромнішою: 11,120 мс проти 2,319 мс для `Add` без місткості (близько 5 разів) і проти 0,389 мс для `Add` з місткістю (близько 29 разів). Так буває, бо `Contains` для `int` порівнює одразу по кілька елементів за інструкцію (векторні інструкції процесора), тож 10⁸ порівнянь виконуються лише за 11 мс.
