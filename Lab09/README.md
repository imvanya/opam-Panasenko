## Завдання 6. Висновки

1. **Порівняння відношення порівнянь на $n = 10 000$:** Наше відношення між простим і швидким сортуванням відрізняється від теоретичного числа 376 через те, що реальна кількість порівнянь залежить від констант у коді, розподілу випадкових даних у масиві та накладних витрат на рекурсивні виклики швидкого сортування.
2. **Чому Array.Sort швидший за власну реалізацію $n \log n$:** По-перше, `Array.Sort` (IntroSort) написано на оптимізованому кешованому нативному рівні середовища виконання .NET. По-друге, він використовує гібридний підхід: на малих підмасивах переключається на сортування вставками, що зменшує накладні витрати на рекурсію.
3. **Вибір алгоритму для потоку даних (100 тисяч записів, ключі 0–300, щоденне сортування, обов'язкова стабільність):** Оскільки ключі мають дуже обмежений діапазон (від 0 до 300), найкращим вибором буде **Сортування підрахунком (Counting Sort)**. Воно має лінійну складність $O(n + k)$, працює надзвичайно швидко для таких обсягів і, що найважливіше, є **стабільним** сортуванням.
